# Circle · 女性健康场景 AI 生活助手

**一个能真跑起来的 AI 对话产品，也是我求职时的一次完整产品实践。**
独立完成：问题定义 → 交互设计 → 提示词与知识体系 → 前后端研发 → **评测体系** → 成本与合规。

| | |
| :--- | :--- |
| **它是什么** | 面向日常生活场景的对话助手，把「女性视角」当作设计默认值，而不是一个附加开关 |
| **核心取舍** | 单次对话成本 < 1 分钱 · 规则记忆而非 LLM · 关键词检索而非向量 RAG · 联网默认 0 token |
| **最值得看的部分** | 一套自建的 **5 维评测体系 + 29 条评测集**，用「检索开 / 关」对照实验量化知识库的真实贡献，而不是凭感觉说"有知识库更好" |
| **工程状态** | 65 个自动化测试全绿 · GitHub Actions CI · Docker + gunicorn 部署就绪 · dry-run 全流程可零 token 自证 |

> **这套评测方法不是凭空来的**：我在实习中做过 AI 编程智能体（Agent）评测任务包的质检——核心工作就是判断「自动判分代码有没有真正覆盖任务要求」，并通过构造坏 case 实锤判分漏洞。Circle 的评测体系，是同一套方法在产品侧的正面应用。

## ⭐ 评测体系（这个项目最值得看的部分）

大模型产品最难的不是"做出来"，是**在没有真实用户的时候，怎么知道它答得好不好**。`eval/` 就是为回答这个问题而建的。

- **5 维评分标准**（`eval/rubric.md`）：医学准确性 / 就医边界 / 共情与语气 / 尊重与不越界 / 幻觉与引用。每一维都配「典型坏回答」锚点，而不是"好 / 一般 / 差"这类抽象描述——**锚点越具体，评分漂移越小**。
- **29 条评测集**（`eval/women_health.json`）：覆盖知识问答、**危急信号识别**（如女性心梗的非典型症状）、诊断与处方边界、情绪支持、网络谣言五类场景。每条在评分前先写 `must_do` / `must_not`（产品预期）——**先定预期、再看回答**，避免被"看起来不错"带跑。
- **主线实验：检索开 / 关对照**（`eval/run_eval.py`）：同一批问题跑两个变体，质量差异即知识库的真实贡献。要回答的是"这套知识库到底值不值"，而不是"我觉得它有用"。
- **双轨打分**：LLM-as-judge 自动打分（温度固定 0 降低漂移）+ 人工抽查表（`worksheet.csv`）校准。
- **诚实状态**：框架与 dry-run 全流程已通（**零 token 自证，不依赖任何 API key**），真实评测待执行——真跑要消耗 token，我把它列为"需要明确批准才做"的动作。

> 直接看代码：[`eval/rubric.md`](eval/rubric.md) · [`eval/women_health.json`](eval/women_health.json) · [`eval/run_eval.py`](eval/run_eval.py)

## 为什么做这件事（起点是用户，不是技术）

市面上的生活/健康助手大多采用「通用默认」设计，而这个"默认"往往不自觉地向男性视角倾斜，于是留下一批没人认真服务的缝隙：

- **健康建议默认以男性生理为基准**：经期护理、非典型心脏病症状、盆底健康……要么被一句带过，要么干脆空白。
- **家务建议默认执行者是"主妇"**：教她更勤快，而不是引导家人共同分担。
- **安全提示很少考虑女性特有的场景**：夜归、独居、需要冷静求助渠道的时刻。
- **情绪表达期待被认真对待**，而不是被一个"抖机灵"的玩笑打断。

**我的假设**：如果在这些场景里，把女性视角当作设计前提而非附加项，同时保持对所有用户友好，就能做出真正「贴心」的产品。

Circle 是这个假设的落地验证。它不做全能助理，只在几个生活场景里把「视角公平」做深。

## 为谁做、在哪些场景做

| 场景 | 用户会这样问 | Circle 如何回应（产品决策） |
| :--- | :--- | :--- |
| 🩸 **经期护理** | "这次特别疼，正常吗？要不要去医院？" | 循证护理 + **明确区分「正常不适」与「需要就医的信号」**，先安抚、再科普、后行动 |
| 🍳 **做饭** | "食谱说 5g 盐是多少？" | 发现"克"对新手不友好，内置生活化参照（茶匙 / 饭碗 / 瓶盖） |
| 🧹 **家务与收纳** | "家里总是我一个人收拾，怎么办？" | 建议中主动带「如何引导家人共同维护」，**不默认女性承担隐形劳动** |
| 💬 **情绪与安全** | "最近很累，没人可说……" | 先共情再建议；遇到不安全信号给出清晰求助渠道；内置女性人物语录自然鼓励，不开轻浮玩笑 |
| 💰 **理财与养老** | "女生怎么开始稳健理财、防被骗？" | 正视「更缺钱、寿命更长、收入偏低」的真实处境，重资金安全与长期规划 |
| 🧰 **实时信息与资料** | "今天天气 / 查最新政策 / 帮我读这篇链接" | 真实信息不靠模型编造：天气/菜谱走免费实时 API；联网搜索失败自动降级；**网页默认只给可点来源，用户说"读一下"才读全文**（成本意识） |
| 📄 **文件阅读** | "看看我这份文档讲了什么？" | 支持近 20 种常见格式（PDF / Word / Excel / PPT / 图片等），让它能"读文档再回答" |

> 每一格的第一列是用户的生活，第二列是她的原话，第三列是"我没有泛泛而答，而是做了什么选择"。

## 产品设计原则（每条 = 一个取舍）

1. **视角公平**：把女性视角当作默认值，而不是开关；健康建议永远区分「正常」与「需就医」。
2. **体谅隐形劳动**：家务话题不默认责任在某一方，把"家人分工"写进建议。
3. **尊重与安全**：认真对待每一种不安全感；涉及求助给冷静、清晰的渠道。
4. **幽默有底线**：真实对话中曾出现冒犯性玩笑 → 在行为准则中显式设限，杜绝拿身体/私生活/性经历开玩笑（无法 100% 保证，因此同时用反馈持续校正——我把它当作需长期治理的问题，而非一次性修复）。
5. **成本即体验**：压到单次 < 1 分钱，才能让用户愿意"随手问"；所有开销可查、有预算上限。
6. **隐私是默认项**：敏感数据默认留在本机，密钥永不入库。
7. **守法与内容合规是硬红线**：绝不输出违反中国法律法规、危害国家安全或国家利益的言辞；合规优先于共情与友好——已写入 SYSTEM_PROMPT 的【内容合规底线】与评测 rubric 的合规红线。

## 我如何判断"做对了"（诚实版）

**当前阶段：个人内测 + 求职展示，尚未公开上线，因此我没有任何留存/活跃数据可以宣称。** 我不打算编造指标来撑门面。

为了下一阶段能用数据说话，我在产品里预埋了仪表，外加一套评测体系：
- **反馈闭环**：每条回答可 👍/👎 + 留言（`feedback/`），沉淀 badcase。
- **成本与用量仪表**：每次调用的 token 与费用自动累计（`cost/daily_usage.json`），让"省成本"是可复现的数据，而不是口头承诺。
- **评测体系 `eval/`**：没有真实用户也能主动发现坏答案——见上文「评测体系」一节（5 维标准，含「绝不违法违规 / 危害国家安全」全局合规红线 + 29 条评测集 + 检索开/关对照 + LLM-as-judge 与人工抽查双轨；dry-run 已通，真实评测待执行）。

**工程护栏**：65 个测试、ruff + pre-commit 门禁——迭代敢下手，因为回归有网兜着。

下一步真正的 KPI，是公开上线后回答这三个问题：谁在用、留下来没有、哪里最卡。详见 [Roadmap](#roadmap)。

## 关键产品决策（我为什么这么做）

| 决策 | 为什么 | 付出的代价 / 下一步 |
| :--- | :--- | :--- |
| **记忆跨会话**，记住称呼/偏好/健康信息 | 生活陪伴的体验靠"它还记得我" | 用规则提取而非 LLM：省 token、可解释、好删改；代价是"换个说法就记不住" → Roadmap：语义检索升级 |
| **知识库用关键词检索，而非向量 RAG** | 71 条结构化知识，关键词命中确定、零额外依赖、零成本 | 召回上限低；把检索接口留成可替换 → Roadmap：混合检索（关键词兜底 + 向量兜底） |
| **回答被截断时自动续写** | "话说一半"是体验事故，不能让用户手动补救 | 续写多消耗 token → 用截断提示兜底，默认最多续 2 轮 |
| **联网"按需读全文"** | 抓取是 0 token 的；只有把正文送进模型才花钱 → 默认只给标题+可点来源，用户明确说"读一下"才烧 token | 多一步交互；换来的是可控成本（网页抓取+缓存已实现） |
| **单页、无账号的极简形态** | 让"从打开到用起来"趋近于零摩擦，先验证核心价值 | 无法多端同步/找回历史 → Roadmap：账号与同步 |
| **单模型（DeepSeek）起步** | 聚焦，先验证产品而非引擎 | 存在单点依赖 → 后续评估多 provider |

> 这一节是我的"PRD 复盘"：**每个取舍都记下了理由和代价**。面试官想看的不是"我全会做"，而是"我知道自己在放弃什么"。

## 我不做什么（范围感同样重要）

- ❌ 不做**医疗诊断**：只给循证护理与"何时就医"的判别，明确不构成专业建议。
- ❌ 不做**社区 / UGC / 排行榜**：陪伴类产品的信任感来自私密与专注。
- ❌ 不在**公开上线前**承诺"数据上云/多端同步"：先把隐私红线设计清楚（见下）。

## 隐私与安全（红线）

- 用户记忆、会话、反馈均为**本地 JSON 存储**，不上传任何第三方服务。
- API 密钥只从环境变量读取，**密钥文件已 gitignore、永不入库**。
- 情绪/健康类敏感字段可一键查看与清除（记忆管理入口）。
- **坦诚边界**：面向公众正式上线前，还需补齐账号体系、传输加密、隐私政策与合规评估——这是我已识别、待执行的公开项，而非忽略项。

## 技术附录（给想跑起来或想了解实现的人）

### 架构（一张图）
```text
浏览器 (templates/index.html，单页，移动端适配)
│  SSE 流式
▼
Flask 后端 (app.py)
├─ 路由：聊天 / 会话 / 记忆 / 反馈 / 上传 / 健康检查
├─ 输入 → 记忆加载 → 知识库检索 → 工具判定 → 拼 System Prompt → 流式生成
│     ├─ 知识库 knowledge/*.json（71 条，关键词 + N-gram 打分，零依赖）
│     ├─ 记忆 memory/（规则提取，本地 JSON）
│     ├─ 工具：天气 / 菜谱 / DuckDuckGo / 联网搜索 / URL 抓取（0 token 优先）
│     └─ 文件 file_parser.py（近 20 种格式正文提取）
├─ 护栏：限流、每日 token 预算、隐私文件隔离、回答自动续写
└─ 本地数据：memory/ · sessions/ · feedback/ · cost/
```

### 技术选型
- **后端**：Python 3.10+ / Flask；**前端**：单页 HTML（内嵌 CSS + JS，无框架）
- **模型**：[DeepSeek](https://platform.deepseek.com) `deepseek-chat`（对话）+ Responses API `web_search`（联网）
- **检索**：关键词匹配 + N-gram 子串打分，零额外依赖（为向量检索预留替换位）
- **质量**：pytest 65 用例 · ruff + pre-commit · 单元/集成双层覆盖
- **评测**：`eval/` 离线自测——5 维 rubric + 女性健康评测集 + 检索开/关 A/B + LLM-as-judge/人工双轨

### 部署（当前状态：如实说明）

> **诚实边界**：本项目定位是**仅求职展示的内测 demo**，尚未公开上线。部署实例上的记忆/会话是服务器本地文件，**重新部署即重置**——正好符合"不长期留存他人数据"。若日后正式公开运营，仍需补齐账号体系、隐私政策与合规评估（见上文红线）。

**已就绪**：`Dockerfile`（gunicorn 生产启动）、`.dockerignore`（key / 隐私 / 测试 / 评测产物均不入镜像）、GitHub Actions CI 自动跑测试、`render.yaml` 作为 PaaS Blueprint 模板。

**关于线上地址——一次如实记录的选型过程**

为了让简历链接**长期可访问**，我评估过几个 PaaS，结论都不合适：

| 平台 | 结果 |
| :--- | :--- |
| Render | 官方文档写明"免费档无需信用卡"，但我实际操作时**两次被强制要求绑卡**，放弃 |
| Railway | 只有一次性 $5 试用额度（30 天），到期容器停止，无法长期挂着 |
| Vercel | 形态不匹配——Serverless 会打断 SSE 流式输出与本地 JSON 状态；且国内基本访问不到 |

**当前计划**：改用**国内轻量云服务器 + 高位端口**。备案针对的是域名而非 IP，使用非 80/443 端口即可在无域名、无备案的前提下访问。部署完成后会把地址补在这里。

**部署后注意**
- 成本护栏已内置：限流 10 次/分/IP + 每日 token 预算；实际开销 = DeepSeek API 按量计费。
- 生产容器不会开 `debug`（有 `PORT` 时自动关闭）；`api_key.txt` 永不提交、永不入镜像。
- `DEEPSEEK_API_KEY` 只在平台环境变量里配置，不入仓库、不入镜像。
